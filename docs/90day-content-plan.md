# 90日コンテンツ計画（非公開の運用資料）

このファイルはサイトに公開されません。`/columns` に載せる記事を、90日かけて順に増やすための計画です。

**前提：12本を一括で自動公開しない。** 1本ずつ、鈴木集が公開前に内容を確認してから出します。

---

## 0. 一次資料と、その扱い方

記事のもとにするのは次の2つです。

| 一次資料 | 頻度 | 使い方 |
|---|---|---|
| 経営日記「ARCH月次総括」 | 日次 | その月に実際に起きたこと・判断したことを拾う |
| 週1回の音声 | 週次 | 日記に書ききれていない、現場での言い回しや温度を拾う |

### 使ってよい部分・使わない部分

- **鈴木集本人が入力した内容**と、**確認済みの資料**を優先する
- **日記に含まれる ChatGPT の回答部分は、事実として使わない**。着想のきっかけとして読むのは構わないが、
  そこに書かれた数字・制度・事例をそのまま記事に持ち込まない
- 制度・診療報酬・統計に触れるときは、厚生労働省など公的な一次資料に当たり直す。当たれないなら書かない
- 医院・施設・患者・スタッフが特定できる情報は、抽象度を上げて書く

### 1本あたりの流れ

1. 日記・音声から題材を1つ選ぶ
2. 事実として書ける部分と、意見として書く部分を分けて箇条書きにする
3. `docs/column-editorial-rules.md` に沿って本文を書く
4. `lib/columns/<slug>.tsx` を1ファイル作り、`lib/columns/index.ts` に import を1行足す
5. **鈴木集が全文を読んで公開可否を判断する**
6. 公開

## note の運用

- **自社サイトの記事をそのまま複製しない**（同じ本文を2か所に置かない）
- 開始は**2か月目以降**。それまでは公式サイトの記事を増やすことに集中する
- 頻度は**月2本程度**
- 内容は、公式サイトの記事を短い体験談へ**再編集**したもの。結論だけを書き、詳細は公式サイトへリンクする
- **今回、note の連携機能やアカウントは作成しない**
