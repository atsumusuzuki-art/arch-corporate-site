## 1. サイトの役割

サービスを詳しく説明して大量集客する営業サイトではない。

紹介された相手が30秒で、次の3点を理解するための「名刺兼実績データベース」とする。

1. ARCHが何者か（歯科医院の外部事務長）
2. 何が強いのか
3. なぜ一度相談する価値があるのか

サイトを見た院長が、「資料を作る会社ではない」「一緒に経営を考えてくれる」「実際に現場を動かす」「最後は医院に仕組みが残る」と受け取れることを完成条件とする。SEOによる大量集客は主目的にしない。

## 2. ブランドと位置づけ

- 中核：**歯科医院の外部事務長**
- ブランドディスクリプター：**DENTAL OPERATIONS PARTNER**（会社名でも商品名でもない。立ち位置を補足する英語表現）
- 日本語の「歯科医院の外部事務長」を主とし、ディスクリプターは TOP の HERO／Footer／会社概要のブランド説明に限定して使う
- HERO の中心コピーは次の表記を維持する

> 歯科医院を、“回り続ける”組織へ。

- ARCHの一文定義：「ARCHは、訪問歯科を入口に、歯科医院の立ち上げ・運営・承継を支える外部事務長会社です。」（この一文を言い換えて意味を狭めない。訪問歯科は入口であり、立ち上げ専門会社には見せない）
- 見せてはいけない姿：単なるコンサル会社／患者紹介会社／営業代行／制作会社／AI会社／資料だけを納品する会社

## 4. ARCHを30秒で

ARCHフィロソフィー Ver.2.0 の仕事の進め方を4項目で示す（2026-09 に旧4項目から差し替え）。

1. 良いご縁から始める — 本当にARCHが役立てる医院と仕事をする。
2. 院長と現場を見る — 数字だけでなく、院長が何に悩み、何を背負っているのかを見る。
3. 現場で実装する — 提案だけで終わらず、人と診療が実際に動く状態までつくる。
4. 仕組みとして残す — ARCHが離れても、医院だけで回り続ける状態をつくる。

## 5. 支援の二層と、卒業

- **運営レイヤー＝終わらせる仕事**：立ち上げ／書類／記録／請求／採用の型／施設営業の導線／院内運用。医院スタッフだけで回る状態にして完了する
- **経営レイヤー＝価値がある限り続ける仕事**：経営判断／制度改定／人の問題／数字の読み替え／施設との関係／次の展開／承継
- 結び：「自走できれば卒業。経営価値が残れば、外部事務長として続く。」
- 契約の継続そのものを成功として表現しない。医院をARCHに依存させない

## 6. サービス

TOPでは二方向だけを示し、細かいサービスを並べない。

| | 見せ方 | ページ |
|---|---|---|
| 01 | 訪問歯科を立ち上げる・再設計する | `/services/visit-dental-consulting` |
| 02 | 医院経営と運営を支える | `/services/external-manager` |

- 外部事務長ページの順序：院長が抱えている負担 → ARCHの役割 → ARCHが担う範囲 → 医院側が担う範囲 → 進め方 → 運営レイヤーと経営レイヤー → 自走・卒業・継続の条件 → 料金 → あわせて読む → 初回適性相談
- 訪問歯科ページは時間軸で整理する：現状確認 → 適性判断 → 体制設計 → 機材・制度・導線 → 施設連携 → 院内運用 → 稼働 → 改善 → 自走化 → 終了または経営レイヤーへ
- 「患者を紹介します」を中心価値にしない
- 新しいサービスページを増やさない。採用・業者連携・DXは「必要に応じて実行体制も組む」と1行添えるにとどめる

## 8. 支援実績の掲載基準

確認済みの事実だけを掲載する。見込み・構想・未着手の領域を実績化しない。医院名は出さない。ARCH単独の成果と断定しない。

### 北海道札幌市
- 実績時点：2026年6月／医院全体の月商：800万円（訪問歯科単独の売上とは書かない。売上の大半を訪問歯科が占める）
- 現在地：訪問歯科を中心とした医院運営を継続して支援中

### 東京都世田谷区
- 訪問歯科をゼロから体制構築／立ち上げ4か月時点／連携施設1件／検診36名／訪問歯科の利用開始15名
- 現在地：訪問歯科の立ち上げ後、施設連携と運営改善を継続して支援中

### 東京都八王子市
- 外部事務長として支援／補助金申請／新たな点数・施設基準の取得に向けた研修会／分院展開の支援
- 現在地：外部事務長として医院運営を継続して支援中
- 院長コメントは、本人の公開承認を得るまで表示しない（`HACHIOJI_COMMENT_APPROVED`）

数字と時点（facts / notes）は変更禁止。「現在地」には時間が経つと古くなる表現（「2026年6月時点」「立ち上げ4か月時点」等）を書かない。

## 9. 支援地域と相談地域

支援実績のある地域と、相談だけの地域を混同しない。地図に表示するのは北海道・宮城県・東京都・神奈川県の4つ。沖縄は「沖縄を含む全国各地から相談」の表現にとどめる。


## 9.9 表記ルール（2026-09-14 統一）

ブランド上の基本表現は `ARCH` ／ `DENTAL OPERATIONS PARTNER` ／ `歯科医院の外部事務長` の3つ。これ以外の言い換えを作らない。

訪問歯科側の呼称は、画面に出る文言では次のどちらかを使う。

| 用途 | 表記 |
|---|---|
| サービス名・ラベル・パンくず・タイトル | 訪問歯科支援 |
| 内容を説明する場面・問い合わせの選択肢 | 訪問歯科の立ち上げ・再設計 |

- 旧称「訪問歯科コンサルティング」は画面に出さない（metadata・構造化データ・パンくず・リンク文言を含む）
- URL `/services/visit-dental-consulting` は SEO 維持のため変更しない
- 問い合わせフォームの相談種別は「外部事務長」「訪問歯科の立ち上げ・再設計」「どちらに当てはまるか相談したい」の3択
- 旧表現「期間を区切った個別のプロジェクト」は使わない。最低契約期間6か月＋原則自動更新という現行の契約条件と矛盾する。代わりに「最低6か月を基本に、医院の状態と支援内容に応じて進めます。」等を使う
- 契約の自動更新と、料金・支援プランの変更は別物。6か月経過後に契約は原則自動更新するが、30万円→15万円へ自動で変わることはない
- 会社概要の「事業内容」は `lib/site.ts` の `COMPANY.business` が正

## 10. 商品・料金・契約（2026-09-14 確定）

正本は `docs/ARCH_PRODUCT_CONTRACT_POLICY_2026-09.md`、サイト実装の参照元は `lib/site.ts` の `PRICING`。金額・期間・条件の変更は鈴木集本人の判断のみ。

| 商品 | 料金 | 期間 |
|---|---|---|
| 初回適性相談 | 無料 | — |
| 標準立ち上げ支援（主商品） | 月額30万円（税別） | 最低契約期間6か月 |
| 自走型立ち上げ支援（条件付き・ARCH側から提案） | 月額15万円（税別） | 最低契約期間6か月 |
| 継続外部事務長 | 月額15万円（税別）を基本 | — |

公開面のルール

- 価格比較を主役にしない。①標準立ち上げ支援 → ②条件付きの自走型立ち上げ支援 → ③安定後の継続外部事務長 の順で、医院の状態・支援段階・実行体制の違いとして見せる
- 自走型は標準と同格の比較カードにしない。「予算に応じた値引きプランではありません。」を明記する
- 初期費用は「支援内容に応じて別途お見積もりする場合があります」にとどめ、固定額を載せない。架空の値引き表示はしない
- 遠方の現地支援（飛行機・新幹線・特急）は交通費・必要な宿泊費が別途。オンライン対応可であることも書く
- 最低契約期間6か月／6か月経過後は原則自動更新／双方1か月前の申し出で終了可能／期間だけでは支援プラン・料金は自動変更しない
- 旧「運営伴走15万／経営伴走30万」の2プラン構造は廃止。復活させない
- TOPに料金は載せない
- 大型・追加案件（新規施設立ち上げ・採用実働・分院・法人化・M&A・補助金・大規模制作）は別途設計。ただし当初合意範囲を後から別料金にしない

**内部契約条件（Webには掲載しない）**：最低契約期間6か月以内の中途解約は原則なし。打ち切り自体は可能だが、残存期間分の料金支払い義務は残る。契約書条文そのものの作成・法務レビューは別工程。

## 11. 初回適性相談

- CTA の表記は「初回適性相談」に統一する
- 見出し：「ARCHと組むべきかを、最初に整理します。」
- 確認すること：医院の目的／現状／体制／資金／訪問歯科との適性／ARCHとの相性
- 無料の範囲に含めないものを明示する：詳細な診断書／実行計画書／資料の作成／同行／実装の責任
- 「何でも無料相談」に見せない
- 公開サイト上の問い合わせ窓口はフォームに統一する。メールアドレスや `mailto:` を画面に出さない

## 12. ARCHの考え方（維持するコピー）

> 良いご縁から始める。実装で価値を生む。仕組みとして現場に残す。
> 医院は自走させる。それでも選ばれる仕事をする。

外部事務長ページ・会社概要では次を維持する。

> 外部事務長は、院長の仕事を奪う人ではありません。院長が本来やるべき仕事に戻るための役割です。
> 調べる時間を、考える時間へ。抱える経営から、任せられる経営へ。

不安を煽る営業コピーにしない。

## 13. デザイン基準

- カラー：Paper `#F7F4EE` / White `#FFFFFF` / ARCH Green `#0F5C3E` / Deep Green `#08533C` / Forest `#2C4A3B` / Pale Green `#E6F2ED` / Light Green `#A7D6B0` / Ink `#1A1A1A` / Muted `#6B716D` / Line `#D5D2CB`
- 比率の目安：Paper・White 約7割／Deep Green・Green 約2割／Pale Green 等 約1割。**Gold は標準色として使用しない**
- 書体：Noto Sans JP（本文・ナビ・ボタン・基本の見出し）／Noto Serif JP（HERO・ARCH Philosophy・代表のことばなど用途限定）／Inter（英字ラベル・番号）
- レイアウト：最大幅1280px、本文幅600〜660px、1px罫線と番号で整理する。カードを大量に並べない
- 角丸0〜4px、影なし、ガラス風UI・過剰な演出・動画背景・スクロールジャックは使わない
- 動きは最小限（240msのフェード＋8px、罫線のline reveal、`prefers-reduced-motion` 対応）
- スマートフォンで短時間に読む前提を維持する

## 14. ロゴとブランド画像

- ロゴは現行の正式ロゴのみ。表示は `components/brand/BrandLogo.tsx` 経由に限定し、参照先は `lib/brand.ts` の `BRAND_LOGO`。新ロゴ案（OPEN ARCH／新Aマーク／新WORDMARK）は使わない。3期目以降の切り替えは `BRAND_LOGO` の差し替えだけで済ませる
- ブランド画像は `public/images/brand/` の4点を「相談 → 判断 → 実装 → 仕組み化」の順で使う
  1. `hero-arch-glass.png` … ARCHを知る（TOP HERO の全面背景）
  2. `director-meeting.png` … 院長と一緒に考える
  3. `implementation-plan.png` … 現場で実装する
  4. `arch-philosophy-books.png` … 仕組みと思想として残す
- これらはブランドビジュアルであり、実在のオフィス・医院の写真ではない。「本社」「当社オフィス」「所在地」等の説明と組み合わせない
- 注記「※サイト内の一部ビジュアルはブランドイメージです。」を Footer に1回だけ表示する。各画像の直下に繰り返さない
- 画像の上にロゴや文字を焼き込まない。コピーはHTMLテキストで置く
- 実写（院長との打合せ、医院内確認、研修、施設打合せ、代表の肖像など）が揃えば、`lib/brand.ts` の `BRAND_IMAGES` を差し替える

## 18. 改修時の判定チェック

- 紹介された相手が30秒でARCHの正体と強みを理解できるか
- 「人物 → 実績 → サービス → 思想」の順序を弱めていないか
- 助言だけのコンサル／患者紹介会社／営業代行／制作会社／AI会社に見えていないか
- 医院をARCHに依存させる見せ方になっていないか（卒業の思想が残っているか）
- 実績として書いた内容は確認済みか。代表者経歴とARCHの支援実績を混同していないか
- 支援地域と相談地域を混同していないか
- ブランド画像を実在施設の写真として誤認させていないか
- 料金・契約条件を鈴木集の判断なしに変更していないか
- スマートフォンで読みやすいか

1つでも外れる場合は、変更の目的と必要性を再検討する。
